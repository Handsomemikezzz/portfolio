# 个人主页：记录做过的东西和变化中的想法

这份文档更新此前的首页内容方向。用户希望参考 [qzq.at](https://www.qzq.at/)，让主页成为个人成长记录，减少求职展示的目的感。之前的 `content-plan.md` 和 `project-directions.md` 仍可作为工程材料的备忘，但其中围绕求职、能力证明和个人优势组织首页的安排已不再适用。

## 新的内容主线

**我在做什么、想什么，这些东西怎样慢慢发生变化。**

用户已确认，个人主页只保留 **项目、写作、旅行、语言学习** 四个内容方向。这些记录一起呈现一个具体的人。记录可以是一件做出来的东西，也可以是一次改主意、一个尚未解决的问题、一段想继续试试的方向。没有必要把每一条记录都写成成果或工程案例。

参考网站用于观察个人内容怎样组织，不复制作者的经历、兴趣、文案或身份。本站仍使用已确认的真实材料。

## 首页怎样组织

1. **个人开场**：姓名、简短自然的介绍，以及通往作品与博客的入口。
2. **做过的东西**：先展示 Aodcast，让访客看到真实应用，再按兴趣进入详细记录。项目数量随实际产物增加。
3. **写下来的想法**：连接已有博客的文章和说说。文章继续在博客仓库维护，本站保留简介与精选入口。
4. **最近在想**：保留 Agent、Jev / Laya 小实验两个仍在规划的项目方向，另给旅行和语言学习各留一个记录入口。明确使用“想试试”“还在考虑”“想记录”等表述，不混入已完成作品或尚未提供的经历。
5. **沿途记录**：有日期依据的变化、迭代和发表记录。以后也可加入本人确认的思考变化，允许文字简短、间隔不固定。

Capabilities、Evaluation、System Design 和个人优势不再作为首页的主架构。无需建立英语、领导力或学习能力的自评模块。语言学习关注过程和真实表达，设计文章可归入项目或写作。AI 社媒的原始计划仍留在 `project-directions.md`，本轮不作为首页主题。

## 项目详情仍然可以写深

Aodcast 的架构、困难、测试、源码和已知限制继续保留，方便想了解细节的人阅读。首页先说它是什么、可以做什么；详情再展开怎么做、为什么改变，以及还有哪些问题。

关于实现的解释可以依据代码整理。个人动机、当时的判断和试错经历需要本人提供，不能从最终代码反推。已有 22 项定向回归记录仍只代表那次明确范围内的验证，不扩大为生成质量或用户效果结论。

## 每次留下一小段即可

下一次值得记录的事情发生时，可以留四项材料：

- **时间与起点**：什么时候，遇到什么问题或产生什么念头。
- **这次做了什么**：一次尝试、一处修改、一段写作或一个产物。
- **现在怎么想**：发现了什么，哪里没想清楚，是否改变了原来的判断。
- **可选附件**：截图、音频、文章、代码或其他真实输出。

没有结果也可以记录尝试；没有做过的事情保持为想法。小记录不必填写完整项目模板。内容积累到足以讲一段完整故事时，再整理进项目详情或博客文章。

## 维护位置

- `src/content/journal.ts`：最近关注、About 简短介绍和记录原则。内容发生变化时直接修改，没有自动推断进展。
- `src/content/projects.ts` 与单独的项目文件：真实作品和详细工程记录。
- `src/content/build-log.ts`：有日期依据的沿途记录；占位条目不进入正式展示。
- `src/content/profile.ts`：公开个人资料、博客与联系入口。

保持已有 `/`、`/projects`、`/projects/[slug]` 和 `/about` 页面，不为每一种兴趣新增页面或后台。优先把这一小批真实内容写得自然、易读，再随生活和项目慢慢扩展。
