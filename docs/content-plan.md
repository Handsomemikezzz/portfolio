## 网站的三条阅读路径

1. **作品**：我做出了什么，访客能看到或试到什么。
2. **工程能力**：我如何构建、设计和评估，具体证据在哪个案例中。
3. **个人优势**：我如何推进项目、表达思考和使用英语，每条都有可核对的经历或作品。

## Agent：建议做一个与已有创作经历相关的任务

候选方向：**创作前的资料研究 Agent**。

用户输入研究问题，Agent 在指定的公开资料中查找和核对来源，生成带引用的简报，经确认后保存到许可的草稿目录。它可以服务于博客、播客和未来的社媒内容，具体任务需在项目启动时确定。

第一版用同一个闭环承载 RAG、Harness、Permissions 和 Evaluation：

- RAG：资料版本、检索结果、引用支持与证据不足的处理。
- Harness：任务状态、工具调用、运行预算、超时、取消与失败恢复。
- Permissions：允许读取什么、写到哪里、何时需要用户确认，由执行层检查。
- Evaluation：同一组任务上的完成情况、引用正确性、失败分布、延迟与实际成本。

Portfolio 至少保留一条成功任务轨迹和一条失败/越界处理轨迹，配一个可运行或可录制的完整示例。

## System Design：现在就有素材，重点补个人决策

Aodcast 可作为当前的系统设计案例，范围是应用层设计与可靠性，不能扩大为未经证明的大规模分布式系统经验。

建议整理三条设计决策：

1. **完成计算与发布结果分开**：任务运行中，用户可能编辑脚本或切换声音；说明最后提交结果时如何检查当前状态。
2. **脚本、声音与音频产物分开建模**：解释 hash / 版本引用的用途，以及它们带来的存储和调试成本。
3. **模型适配与业务编排分开**：解释 provider 能力差异怎样传递到流程，为什么把哪些职责留在适配层。

每条决策用一个短记录：背景与约束 → 考虑过的方案 → 最终选择 → 代价 → 如何验证 → 什么情况下需要改变。

代码只能证实当前实现；当时为什么选这个方案、是否尝试过其他方案，需要本人补充，不能从代码反推一段虚构经历。

## Evaluation：用完整的实验闭环证明

当前 22 项 mock 回归检查用于核对 Aodcast 的特定行为。它们的来源、执行日期与范围已有记录；个人测试设计职责尚需具体叙述。这些数字不代表真实 Agent 任务成功率、语音质量或全部项目测试覆盖。

未来的代表材料可以来自 Agent 或 Jev / Laya 实验：

1. 定义任务、成功标准和人工标注规则。
2. 固定数据与模型版本，分开调试集和留出的测试集。
3. 建立基线，选择一个实际策略变更。
4. 在相同条件下比较，保留逐项输出、错误类型与未改善的案例。
5. 说明结果如何影响产品或系统决策，而非仅展示一个总分。

需要的公开材料：小型可复查样本、评分说明、复现命令、结果摘要和失败分析。没有提升也可以成为有价值的实验结果。

## 英语与个人优势

英语按实际能力拆开表达：阅读理解、书面表达、口头沟通，以及真实协作使用经历。可以只展示其中有依据的部分。

优先收集：

- 本人用英语讲解 Aodcast 或 Agent 的短视频，说明问题、流程和一个设计取舍。
- 一篇本人能解释并维护的英文项目摘要或技术文章。
- 如果确实存在，补充英语考试名称、分数、日期，或英文会议、客户沟通、开源讨论经历。

英文产品输出可以证明产品能力；本人英文讲解用于展示个人沟通能力。AI 编辑或生成材料不应被用来暗示未经证实的独立语言水平。

| 个人优势候选                 | 目前依据                             | 下一份材料                                             |
| ---------------------------- | ------------------------------------ | ------------------------------------------------------ |
| 产品设计与主要开发           | 本人已确认 Aodcast 的职责            | 从需求到可演示版本的一段推进过程、范围取舍与本人贡献   |
| 产品判断                     | Aodcast 存在脚本中心工作区等具体设计 | 本人解释原来哪里难用、怎样判断和修改，以及观察到的结果 |
| 技术表达与复盘               | 已有个人博客和 AI 辅助开发相关文章   | 精选一篇与项目决策相关的文章，关联实际案例             |
| 英语沟通                     | 本人希望突出，具体依据待补充         | 本人英文演示、英文文章、成绩或使用经历                 |
| 学习适应、团队协作、领导力等 | 尚未确认                             | 一件可叙述的真实事件；没有实例前不写成网站优势         |

## 建议推进顺序

1. 补齐 Aodcast 的当前演示和一条设计决策，先充实已有作品。
2. 收集英语证据及个人优势实例，先做 About 的少量真实条目。
3. 选定 Agent 的任务，按真实运行需要设计 RAG、Harness 和权限层。
4. 以 Agent 或 Jev / Laya 实验形成完整评估报告，支撑 Evaluation 能力。
5. 把英文讲解、技术文章和演示素材复用于博客与社媒；无需为每项优势分别再做一个项目。
