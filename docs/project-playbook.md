# 用 Aodcast 学会沉淀一个项目

目标：让别人能看到作品、理解你的决策，并找到支持结论的材料。
内容不必一次完整；有明确证据的小案例，比填满所有栏目更有用。

## Aodcast 下一步最值得补的三件事

### 1. 一个完整且可公开的创作样例

选一段你自己写的、可以公开的 Markdown，长度适合生成 30–60 秒音频。保留：

- 输入原文与最终脚本。
- 一段录屏：导入 → 修改脚本 → 选择声音 → 试听 → 导出。
- 最终真实音频，以及使用的模型版本和设置。

录屏不需要宣传片包装。重点是让别人看见一次真实工作流。使用可以公开展示的声音和素材；避免把本地目录、账户信息或私有内容录进去。

### 2. 当前版本的两三张截图

- Episode Workspace：脚本与声音、音频操作如何共处。
- 正在生成或取消任务：用户如何知道系统在做什么。
- 修改脚本后保留旧音频：展示状态管理如何影响产品体验。

现有封面是历史材料，不要仅换日期就称它为最新版本。
新截图可放在 `public/images/aodcast/`，更新 `cover` 的路径、说明和实际宽高。

### 3. 一次有条件说明的真实测量

开始不需要大型 benchmark。先固定输入、模型、硬件和设置，记录多次运行的：

- 能否完成导出、失败阶段和失败原因。
- 首次试听等待时间、完整生成时间。
- 音频是否丢字、重复、异常停顿，哪些问题由人工听评发现。

需要保留原始记录、运行次数、日期、模型版本与缓存状态。不要把单次体验推广成普遍成功率，也不要把本次单元测试耗时写成音频生成延迟。没有测过的成本、自然度和说话人相似度继续留空。

## 以后每个项目的最小材料包

每次完成一个可以演示的版本，保存下面这些即可：

1. **作品**：一张真实封面，或可播放的音频 / 视频 / 在线入口。
2. **背景**：谁遇到了什么问题，你选择了什么范围。
3. **职责**：你实际负责什么，哪些来自协作或第三方。
4. **决策**：一个具体失败或取舍，采用的方法，以及为什么。
5. **证据**：可复现测试、输入输出、任务轨迹或真实测量，写清来源和局限。
6. **版本**：对应的 commit / release、日期及仍未解决的问题。

原始开发日志、完整代码、私有资料仍留在原项目。Portfolio 只收录经过选择的公开材料。

## 内容如何进入现有网站

简单项目继续直接添加到 `src/content/projects.ts`。较长案例可以仿照 `aodcast.ts` 单独建一个 TypeScript 数据文件，然后导入 `projects` 数组。

- `featured`：是否进入首页重点作品；目前仍显示前三个。
- `cover`：真实图片路径、alt、caption、可选实际宽高。
- `evaluation.metrics`：只填写实际测量值，`context` 写条件，`source` 链接报告。
- `references`：代码、报告、版本、来源链接。
- `demo.linkLabel`：区分“本地运行步骤”和真实可用的“在线演示”。
- `contentLanguage`：正文语言，中文使用 `zh-CN`。
- Build Log：记录一次真实交付或验证，并链接回项目，不把计划写成已完成成果。

## 本地项目候选

只依据名称或本地目录不创建个人贡献案例。再次整理前，先确认本人的贡献、项目是否已到可展示状态，以及哪些截图和数据允许公开。

- `waytofree`：本人明确选择不纳入作品集，交易相关内容不再作为后续候选。此决定是内容定位选择，与仓库是否存在未提交改动无关。
- `hn-blog`：确认为个人博客仓库，也有文章、说说和旧项目列表。未来可作为个人发布与本地 Markdown 内容维护案例；已有数据中的 AI Copilot 描述需要先确认它对应哪个实际仓库、哪些部分本人实现。
- `TradingAgents`：本地仓库的 origin 指向 TauricResearch 上游；在确认 fork 与实际贡献前，不把上游框架写成个人作品。
- `UZI-Skill`：仓库中声明的作者是 `FloatFu-true`，origin 指向 `wbh604/UZI-Skill`。在确认具体贡献前，只能作为使用或贡献记录，不能直接算作本人的项目。

`src/content/capabilities.ts` 保留为历史能力映射备忘，已不用于首页。个人记录方向见 [个人记录方向](personal-journal-direction.md)；项目中的事实、测试和来源仍应可核对。

如果以后放音频，可先在项目仓库或稳定作品平台提供播放链接，再填入 `demo.url`；当前组件不会自动把 URL 变成播放器。长视频同理，无需为了一个案例引入媒体后台。

完成后运行 `npm run check`，并检查作品列表、详情页、证据链接和手机布局。
